**Règles critiques à ne jamais oublier, même sans avoir lu le détail :**
- Auth : jamais de token en `localStorage` (cookies httpOnly + CSRF). Anti-brute-force sur tout point d'entrée d'authentification.
- Toute vue qui liste des ressources sensibles applique le scoping de périmètre (entreprise du recruteur via `get_entreprise_for_user()`, candidat via `request.user`).
- Une exigence de permission/palier se vérifie par un test d'intégration sur une vraie route métier, pas sur le défaut global.
- Données candidat masquées avant déblocage CVthèque (`ProfilCandidatDTO._peut_voir_coordonnees`) : tout nouveau champ identifiant doit suivre ce garde.
- Un déblocage CVthèque n'est **jamais** un accès permanent : tout accès recruteur à des données candidat fondé sur un déblocage ou un partage doit passer par `credits_utils.profil_accessible_aux_recruteurs` (compte actif ET profil visible). Ne jamais écrire « à vie » dans l'interface. Les documents privés ne sont exposés que par `PartageDocument` explicite.
- Pas de `window.confirm`/`prompt` : `confirmToast` ; pas de couleur en dur : tokens `tw.*` de `theme.js`.
- **Notifications** (21/10/2026) : toute notification passe par **`utils/notifier.js`** (`succes`, `erreur`, `echec`, `info`, `chargement`, `fermer`), jamais par `react-hot-toast` directement (test d'architecture `tests/notificationsCentralisees.test.js` : seuls `utils/notifier.js` et `Components/NotificationsHost.jsx` l'importent). Une seule apparence : `NotificationsHost` (position et durée) + carte `Notification.jsx` + jetons `notif*` de `theme.js`. **Écriture** : un titre court, sans point ni « ! » (« Profil mis à jour », « Connexion réussie »), un détail facultatif sur la ligne suivante ; un échec d'appel serveur s'écrit `notifier.echec("Suppression impossible", err)` (le détail est le message du serveur, sinon « Veuillez réessayer dans quelques instants. ») ; une validation de formulaire s'écrit `notifier.erreur("Titre manquant", "Le titre est obligatoire.")` ; une opération longue : `const id = notifier.chargement("Connexion en cours")` puis `notifier.succes("Connexion réussie", undefined, { id })`. Titre et détail voyagent dans une seule chaîne `"Titre\nDétail"` : les tests (qui moquent `react-hot-toast`) assertent cette chaîne.
- Soft-delete par défaut ; toute suppression en masse : liste validée, sauvegarde, normalisation de chemin.
- Référentiel : toute fusion/équivalence passe par `referentiel_fusions.py` puis `consolider_referentiel`, jamais en shell (la suppression de doublons de métiers aussi : `supprimer_doublons_metiers`, liste validée, sauvegarde avant, rejouée après chaque import). Un métier actif pointe vers lui-même ou n'a pas de valeur : ce n'est pas une équivalence (`metier_canonique_id not in (None, id)`).
- **Métier de référence d'une offre = interne** : le recruteur garde son intitulé public (`titre`), rattaché en interne à un métier de référence qui ne sert qu'au calcul ; il n'est **jamais** montré au public ni aux candidats (seulement au recruteur et à l'admin). `OffreEmploiSerializer` le retire par défaut (`metier`, `metier_libelle`) ; ne l'exposer qu'avec `context['inclure_metier_reference']`, jamais dans une réponse publique.
- Listes de secteurs : toute liste proposée à l'utilisateur passe par `referentiel_utils.trier_secteurs` (ordre alphabétique sans accent, sur le libellé nettoyé) ; jamais l'ordre de la base ni celui des lettres ANEM.
- Espace recruteur : une entreprise non validée n'a accès à **aucune** route métier (403 `ENTREPRISE_NON_VALIDEE` dans `CustomJWTAuthentication`, écran d'attente `EntrepriseValideeGuard`) ; une nouvelle route recruteur est couverte automatiquement tant qu'elle n'est pas `AllowAny`. Une relation inverse mal nommée (`profil_entreprise`, pas `profilentreprise`) fait échouer le garde **sans erreur** : le tester par cookie JWT réel, jamais par `force_authenticate`.
- Demandes d'ajout au référentiel (diplômes, spécialités, métiers, compétences ; étapes 1 à 3 livrées, nettoyage des anciennes routes/`PropositionMetier`/`AdminMetiersSuggeres.jsx` en attente des commandes `migrer_*_vers_demandes` en production) : tout nouveau cas passe par `jobs/demandes_ajout/` (même vocabulaire, mêmes trois décisions, jamais d'effet avant décision de l'admin) ; une décision ne modifie jamais une offre publiée ; une formation « à préciser » ne se marque pas « refusée » par `save()` (il la remettrait à « déclaré ») ; seul « Autre diplôme » (`D-AUTRE`) crée une demande de type de diplôme (l'intitulé `diplome` d'une formation sans type n'en est jamais une).

Le parser n'écrit jamais `specialite_texte`. Un jeton de masquage (`[NOM]`…) recopié par l'IA est restauré ou retiré par `cv_parser/jetons.py` avant l'enregistrement du profil.

Chaque ligne = autant de cellules que d'en-têtes.

L'admin simple garde la lecture de la page (consommation), les interrupteurs et les quotas : ne pas la verrouiller en entier. Toute écriture de configuration IA, y compris la création/suppression d'un quota personnalisé par compte, est tracée (`MODIFIER_CONFIG_IA`). Tout nouveau champ de configuration qui change le coût ou le destinataire des données candidat suit le même garde (constante dans `serializers/ai_config.py`, drapeau `*_modifiable`, champ désactivé et jamais renvoyé côté écran, test sur la vraie route `admin-ai-config`).

Ne pas ajouter de cache de pages HTML (versions périmées). Changer `VERSION` purge les caches. nginx doit servir `sw.js` sans cache (voir deploiement.md).
- **Images envoyées** : tout `ImageField` des modèles de `jobs` est optimisé automatiquement à la sauvegarde (`jobs/image_utils.py`, signal `pre_save` branché dans `JobsConfig.ready`) : 1600 px max, recompression, EXIF supprimé (position GPS) ; un ImageField d'une autre application doit être ajouté à `APPS_CONCERNEES`.
- **Formulaires** : message sous chaque champ avec `useErreursChamps` + `FieldError`, `noValidate` sur le formulaire, effacement dès la correction ; le toast reste en complément. Ne pas désactiver la validation native d'un formulaire dont certains champs (listes de diplôme/spécialité) en dépendent sans la remplacer.
- Coordonnées et informations de la société : **jamais en dur**. Source unique `MentionsLegalesEntreprise` (Admin → Mentions légales et coordonnées), lue via `utils/informationsSociete.js` (front) et `informations_societe.ligne_pied_de_page` (PDF). Un champ vide n'est pas affiché. Aucune « validation institutionnelle » (ANPDP, agrément…) sans justificatif détenu.
- Données personnelles (sexe, âge, service militaire, permis, véhicule, passeport) : jamais dans le score ; filtres CVthèque correspondants seulement via une exigence d'offre de même catégorie ; questions disqualifiantes : justification obligatoire, critères protégés refusés (`questionnaire_validation.py`).

## Règles d'organisation du code (impératives)

1. **Aucun fichier de code au-dessus de 1000 lignes.** Cible : 200-400 lignes, plafond doux 800. Au-delà on découpe par responsabilité (voir [carte-du-code](docs/architecture/carte-du-code.md) pour les découpages déjà faits).
2. **Un dossier = un sujet.** Un fichier = une responsabilité, nommé pour ce qu'il contient (`cv_parser/sections.py`, pas `utils2.py`).
3. **Les anciens chemins d'import restent valides** : un package découpé garde un `__init__.py` qui réexporte tout (`from jobs.models import X` marche toujours).
4. **Après chaque découpage** : `python manage.py check`, tests ciblés, puis `npx vite build` (frontend). Jamais de découpage sans test vert.
5. **Documenter** : chaque nouvelle session va dans `docs/journal/`, chaque nouveau découpage dans `docs/architecture/carte-du-code.md`.

## Pièges à ne pas oublier (appris à la dure)

- Après `makemigrations`, lancer **immédiatement** `migrate` (sinon `ProgrammingError` au premier test).
- Jamais `.filter(...).first()` sans `order_by` ni mutation de données via `manage.py shell` sur la base de dev réelle : utiliser `.get(email=...)` ou une base de test.
- Ne jamais définir un composant React **à l'intérieur** d'un autre composant à state local (démontage à chaque frappe, formulaire inutilisable).
- Tout nouvel appel `jobsService.*` dans un composant testé doit être ajouté au mock du test correspondant (sinon échec silencieux).
- `AIConfig.*_prompt` en base **prime** sur la constante du code : resynchroniser après modification d'un prompt.
- Frontend : préférer `npm run build` à `npx vite build` si npx prend une mauvaise version de Vite.
- Ne pas modifier des fichiers par script (sed/python) : utiliser Edit pour que les changements soient visibles dans l'éditeur. Le hook GateGuard exige d'énoncer des faits avant la première écriture de chaque fichier.
- Fichier temporaire `CORRECTIONS_CLIENT_TEMP.md` : déplacé dans `docs/archives/`.
